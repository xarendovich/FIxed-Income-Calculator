# The owner's daemon taxonomy, reconciled against contract 5.0.0

- **Source:** the owner's breakdown of "what a daemon can be and do within the Spark Core architecture" (2026-10-08), given as the intent the standard pattern was built to. Checked line by line against the code, the contract and the decision log, so that what is built, what is only recorded, and what contract 5 rules out are not confused.
- **Reading the verdicts:** **Built** = enforced in code and held by a test or battery check. **Recorded** = adopted or proposed in the decision log, not implemented. **Not available** = contract 5 forbids it as stated, with the rule that does.

## 1. Daemon types

| Type (owner's words) | Verdict | What the pattern actually does, and the corrections |
| --- | --- | --- |
| **Passive Observers** — continuous background *systemd user services* monitoring filesystem and *Git HEAD* transitions, no remediation | **Built, with two corrections** | This is class 1, Observe, the only class unlocked; every reference daemon is one. *Correction 1:* the generated unit is a **system** service with a dedicated user by default (PD-09: `run_as: {unit: system, user: …}`); user units are generated with a warning because their sandboxing is unverified. *Correction 2:* since contract 5 a daemon runs no program (R-2), so Git HEAD cannot be observed by running `git`. It **can** be observed as files: `.git/HEAD`, `.git/refs/heads/*`, `.git/packed-refs` are ordinary readable files under a declared read, and nothing in the base deny list covers `.git`. A file-based HEAD observer is within the contract; `git-watch` left because it ran a program, not because the observation is forbidden. *Bound:* "available" is not "declare the repository root": a declared read of `.git` is a path grant like any other, a planted link under it is a policy stop (exit 78), and E-4 (which layer refused) is still open. |
| **Active Survival Constructs ("Blind Forester")** — intercept downstream failures and shift into a pre-validated degraded survival loop | **Adopted by owner ruling (PD-01.9, 2026-09-30); not available in contract 5** | PD-01.9 was adopted by the owner as a core pattern on 2026-09-30 with conditions BF-1 to BF-6. The contract says it plainly: "a pre-validated survival loop (PD-01.9) is not available in contract 5; it requires an Act-family class, the supervisor/worker split (PD-72) and pre-authorized survival." `act` stays reserved (PD-60). So it is a class to unlock, gated on two things that do not exist yet. |
| **Wrapped External Daemons** — IoT sensor pollers, network health monitors, disk gauges bolted into a Spark wrapper under a declarative schema | **Not a category; folded** | Reviewed 2026-10-08 (`ADJUDICATION-ALIGNMENT-REVIEW.md`, item 1). Where the external thing exposes **files** (a disk's statvfs, sysfs, a device node under a declared read) the daemon is simply a **Passive Observer**, class 1: `disk-watch` is one, built. Where it is a **process** to be run or wrapped, it is outside the generic core: contract 5 runs no program (R-2) and grants execute nowhere; the adjudication records that a command-backed extension would be designed outside the confined process (PD-72) and is not this core's. *Network health monitors* are out either way: `network.mode` admits only `none`, `named` is reserved (PD-42), and the unit sets `PrivateNetwork=yes`. The owner's term is kept here as the label of what was asked, so the correction is visible; it should not be used as a class name. |

## 2. Core functions and capabilities

| Function (owner's words) | Verdict | What is there, and the corrections |
| --- | --- | --- |
| **Continuous execution and liveness** — always-on, idle polling, `Type=notify` watchdog kills and restarts hung loops | **Built** | `Type=notify`, `NotifyAccess=main`, `WatchdogSec = 2×cycle_budget + 10`, pings only from the main loop so a hung `sense()` starves them (DB-11 proves it), `TimeoutStopSec` outlasting one watchdog period (HF-31). *Precision:* exits 2, 65, 73 and 78 are **never** restarted (`RestartPreventExitStatus`, HF-28); only a crash and exit 70 are. "Automatically restart" holds for hangs and crashes, not for fail-closed stops, which need a person. *Bound on exit 70:* it means an uncertain ledger commit, and the restart recovers the pattern's own ledger (tail quarantine, U-6). It is a process exit class, not a class privilege, and not the `UNKNOWN_AFTER_RESTART` outcome of any other contract; a consumer may call it the nearest analogue, never the same thing. |
| **Mechanical observation** — code transitions recorded mechanically into an append-only hash-chained ledger (`timeline.jsonl`), never mutating the runtime database | **Built, one name differs** | The ledger is `ledger.jsonl` (`spark-daemon-ledger/1`): append-only, hash-chained, canonical JCS, one writer, two independent verifiers. `timeline.jsonl` is the Observer's name for its own ledger; whether the two share one durable writer is PD-56, pending. The runtime database is never touched: `~/spark-core/data` is base-denied. |
| **Zero-action restraint** — forbidden from modifying the repository, running tests, or autonomous repair; "takes notes" | **Built** | I-1 and I-5: observe only; no program is run; the output directory is the only writable place and may not overlap a read; a policy violation fails closed (78). Stronger than stated: it cannot run *anything*, not only tests. |
| **Elastic resource yielding** — `CPUWeight=10` to parse fast when idle and yield instantly to LLM inference | **Built, with a claim corrected** | The unit sets `CPUWeight` (manifest, default 10 in the examples), `Nice=10`, `IOSchedulingClass=idle`, `MemoryMax`, `TasksMax`; DB-14 projects the CPU share against `cpu_budget_bp`. *Correction:* `CPUWeight` is **proportional sharing** under contention, not instant preemption; with weight 10 against a default of 100 the daemon gets about a tenth of a contended CPU, and the cycle budget bounds how long one cycle may take at all. "Instantly yield" overstates a cgroup weight. *Open:* memory is still measured as process RSS; the cgroup `memory.peak` reading the owner adopted (PD-76) is DB-19, reserved and not built. |
| **Isolated sandboxing** — Landlock blocking TCP and unauthorized writes; strict `manifest.json` schema | **Built** | Landlock ABI ≥ 1 required at every start (no tolerance since contract 5), TCP blocked from ABI 4, execute granted nowhere; one `PathPolicy` projected into Landlock, the audit hook and the unit, with an agreement test; manifest schema 4 is closed (no unknown keys). DB-13, DB-17, DB-18. |
| **Supervisor/worker process split** — a supervisor owns the watchdog and ledger and spawns `daemon.py` as an isolated child worker | **Not built; recorded as the future shape** | Contract 5 runs `daemon.py` **in-process**, confined by purity (a tripwire), the audit hook (a tripwire) and Landlock (the boundary). The audit hook blocks `os.fork` and every spawn, so the current process cannot split itself. The split is AP-04/PD-72, recorded, and it is a stated precondition of the Blind Forester. The r4.9 owner ruling PD-101 ("the kernel is the boundary; purity and the audit hook are diagnostics") is what makes the single-process design acceptable today. |
| **"Bolt-on" extensibility** — three functions, `sense`, `decide`, `digest`; the framework owns safety, state and concurrency | **Built, exactly** | `sense(ctx)`, `decide(prev, snapshot)`, optional `digest(snapshot, recent)`; the contract publishes the signatures; everything else is the skeleton's and an author cannot touch it. This is the "stable contract / replaceable decision maker" split the owner described. |
| **T/2 heartbeat continuity** — a restarted survival daemon reads the T/2 heartbeat, recognises its blind state, bypasses timeouts and resumes the degraded loop | **Half built** | *Built:* `DAEMON_HEARTBEAT` every `blind_limit/2`; blindness survives restarts on the boot clock (PD-70, HF-32, HF-34); a restart that inherits more than the limit gets exactly one reacquisition cycle, then `SENSE_BLIND` (78, never restarted). *Not built:* "resume the degraded loop" is the Blind Forester's behaviour, gated as above. For an Observe daemon the designed outcome of persistent blindness is to **stop for a person**, not to keep going. |

## 3. What this reconciliation changes

Nothing in the code. Three things in the record:

1. **The taxonomy is a class ladder of two, not three mechanisms.** Passive Observer = class 1 (built). Blind Forester = an Act-family class (adopted by owner ruling, gated on PD-72 and the `act` unlock). "Wrapped external daemon" is not a class and is folded: a file-exposed source is a Passive Observer; a process is PD-72, outside the core.
2. **Two statements to correct wherever they are repeated:** daemons are system services with a dedicated user, not user services; and a daemon runs no program, so "Git HEAD" is observed by reading `.git` files, and "wrapping" an external process is not what the core does.
3. **Two things the owner's list assumes that are not built and should stay visibly open:** the supervisor/worker split (PD-72) and the cgroup memory reading (DB-19/PD-76).

For the Advise class the owner confirmed, and where its model sits, see `HANDOFF-PD-51-L2-EVENT-TYPES.md` §5.
